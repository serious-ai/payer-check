This page works like a calculator that lives inside your web browser. Your report is read right here on your screen, and the copies save back to your own computer. Want to see for yourself? Once this page has loaded, turn off your Wi-Fi and run it. It works the same.

For your IT team: how to verify this in a few minutes
  1. Save this page, disconnect from the network, open the saved copy and run it. It works the same.
  2. Open the browser's developer tools, go to the Network panel and run it. The list stays empty.
  3. Read the page's first lines. Its Content Security Policy (default-src 'none'; connect-src 'none') tells the browser to block every fetch, upload and outside file the page could ask for. The policy doesn't govern the page sending the tab elsewhere, so the page has no links and no code that opens another site.
  4. Read the source. It's one file with nothing loaded from anywhere, and the code is public with an automated test that fails the build on any network request.

What it does


Safe Harbor, column by column


    

  • Account, encounter, claim and member numbers become random codes. A code isn't made from anything about the patient, and the same number always gets the same code, so lines from one visit stay together.
    • 

  • Every date becomes its year. When a report has a service date and a payment date, the days between them are worked out first and added as a column.
    • 

  • Names, addresses, phone numbers and birth dates are dropped. Ages over 89 show as 90+.
    • 

  • Amounts, codes, payer and provider names stay. Any date, phone number, email or long number typed inside them is replaced.
    • 

  • Free-text notes and columns it doesn't recognize are dropped, and the record names them.
    • 



No AI runs here, only plain rules anyone can read in this page's code. One part stays with you: before sending, make sure nobody at the practice knows of a way the remaining details (a rare procedure, a very small payer) could point to a particular patient.
